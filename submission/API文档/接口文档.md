# LabelHub 接口文档

## 0. 文档定位

本文档按系统功能说明 LabelHub 当前有效的后端 HTTP API,用于前后端联调、验收和二次开发。完整 OpenAPI schema 以运行时 Swagger 为准:

- Swagger UI: `https://www.scu-gpt.top/labelhub/swagger-ui/index.html`
- OpenAPI JSON: `https://www.scu-gpt.top/labelhub/v3/api-docs`

本文档只保留当前有效接口和当前业务口径,不再记录历史日期变更说明、已删除接口或未实现预留接口。历史实现过程查看 `submission/相关文档/阶段计划.md`、`submission/相关文档/阶段实现.md` 和 `submission/相关文档/问题点归档.md`。

## 1. 通用约定

### 1.1 基础路径与部署路径

- 本地后端 API 基础路径: `/api`。
- 前端通过 `VITE_API_BASE_URL` 拼接 API 地址,默认值为 `/api`。
- 子路径部署时,浏览器 API 入口可配置为 `/labelhub/api`,网关再转发到后端 `/api`。
- 本文档中的接口均以真实后端路径 `/api/...` 描述。

### 1.2 鉴权

- 登录、注册和忘记密码接口公开访问: `POST /api/auth/login`、`POST /api/auth/register`、`POST /api/auth/password-reset/code`、`POST /api/auth/password-reset/confirm`。
- 邀请链接校验接口公开访问: `GET /api/auth/reviewer-invitations/validate`、`GET /api/auth/owner-invitations/validate`。
- Swagger 相关路径公开访问。
- 其它 `/api/**` 接口都需要 `Authorization: Bearer <accessToken>`。
- 权限主要按角色控制: `owner`、`labeler`、`reviewer`、`ai_reviewer`、`system_agent`。

### 1.3 响应格式

普通 JSON 接口直接返回对象或分页对象。分页对象统一为:

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0
}
```

文件下载接口返回二进制流,通常带 `Content-Disposition` 文件名。

SSE 流式接口返回 `text/event-stream`,事件包括 `delta`、`result`、`done`、`error` 等。

### 1.4 错误格式

统一错误响应结构:

```json
{
  "code": "ERROR_CODE",
  "message": "human readable message",
  "invalidItems": []
}
```

常见错误码:

- `UNAUTHORIZED`:缺少 token、token 无效或用户不存在。
- `FORBIDDEN`:当前角色无权访问。
- `VALIDATION_ERROR`:请求体 Bean Validation 校验失败。
- `RESOURCE_NOT_FOUND`:请求路径不存在。
- `INTERNAL_ERROR`:未预期后端异常。
- 业务错误码按模块返回,例如 `TASK_NOT_FOUND`、`DATASET_NOT_FOUND`、`ANNOTATION_NOT_FOUND`。

### 1.5 时间与状态

- 时间字段通常为后端格式化字符串或 ISO 字符串,前端按展示场景格式化。
- 任务状态: `draft / published / paused / ended`。
- 标注答案状态: `DRAFT / SUBMITTED / AI_REVIEWING / REVIEWING / RETURNED / ACCEPTED / EXPORTED / VOIDED`。
- 人工审核动作: `APPROVE / RETURN / REVISE / ESCALATE`。
- AI 预审决策: `PASS / REJECT / NEED_HUMAN_REVIEW`。

## 2. 认证与邀请

### 2.1 功能说明

认证模块负责登录、注册、当前用户查询、退出登录、Reviewer 邀请和 Owner 邀请。普通注册默认创建 `labeler`; 使用 Reviewer 邀请 token 注册创建 `reviewer`; 使用 Owner 邀请 token 注册创建 `owner`。
忘记密码通过邮箱验证码完成,发送验证码前需要 Turnstile; 已有邮箱账号必须匹配原邮箱,无邮箱账号可在验证码重置成功后首次绑定该邮箱。

### 2.2 典型流程

1. 用户打开登录页。
2. 普通用户调用 `POST /api/auth/register` 创建 labeler 账号,或使用邀请链接先调用 validate 接口校验 token。
3. 登录调用 `POST /api/auth/login`,拿到 `accessToken`。
4. 后续接口统一带 `Authorization: Bearer <accessToken>`。
5. 进入应用后调用 `GET /api/auth/me` 获取角色和权限。

### 2.3 接口列表

- `POST /api/auth/login`
- `POST /api/auth/register`
- `POST /api/auth/logout`
- `GET /api/auth/me`
- `POST /api/auth/password-reset/code`
- `POST /api/auth/password-reset/confirm`
- `POST /api/auth/reviewer-invitations`
- `GET /api/auth/reviewer-invitations/validate?token=...`
- `POST /api/auth/owner-invitations`
- `GET /api/auth/owner-invitations/validate?token=...`

### 2.4 关键接口说明

`POST /api/auth/login`
- 权限:公开。
- 请求关键字段:`username`、`password`、可选 `role`、`turnstileToken`。
- `role` 可用于指定登录工作台角色; 用户不具备该角色时返回 `ROLE_MISMATCH`。
- `system_agent` 可通过 `X-LabelHub-Service-Login-Token` 绕过 Turnstile,仅用于系统 Agent。
- 响应关键字段:`accessToken`、`tokenType=Bearer`、`expiresIn`、`user`。

`POST /api/auth/register`
- 权限:公开。
- 请求关键字段:`username`、`password`、可选 `inviteToken`、`ownerInviteToken`、`turnstileToken`。
- `inviteToken` 和 `ownerInviteToken` 不能同时提交,否则返回 `MULTIPLE_INVITATIONS`。
- 无邀请 token 时创建 labeler; Reviewer 邀请创建 reviewer; Owner 邀请创建 owner。
- 常见错误:`USERNAME_EXISTS`、`INVALID_INVITATION`、`INVITATION_EXPIRED`、`INVITATION_USED`、`INVALID_OWNER_INVITATION`、`OWNER_INVITATION_EXPIRED`、`OWNER_INVITATION_USED`。

`POST /api/auth/reviewer-invitations`
- 权限:仅 owner。
- 响应:`token`、`expiresAt`。
- 邀请 token 24 小时有效,单次使用。

`POST /api/auth/owner-invitations`
- 权限:仅 owner。
- 响应:`token`、`expiresAt`。
- 用于已登录 Owner 邀请新的负责人账号。

`GET /api/auth/me`
- 权限:登录用户。
- 响应:`user` 和 `permissions`。

`POST /api/auth/password-reset/code`
- 权限:公开。
- 请求关键字段:`username`、`email`、`turnstileToken`。
- 发送前校验 Turnstile,并用 Redis 控制验证码有效期、重发冷却和尝试次数。
- 已有邮箱账号必须提交账号原邮箱; 无邮箱账号允许提交首次绑定邮箱。
- 为避免账号枚举,账号不存在、账号禁用或邮箱不匹配时仍返回通用成功提示,但不会发送邮件。
- 响应关键字段:`message`、`expiresInSeconds`、`resendCooldownSeconds`。
- 常见错误:`TURNSTILE_REQUIRED`、`TURNSTILE_FAILED`、`PASSWORD_RESET_CODE_COOLDOWN`、`MAIL_UNAVAILABLE`、`MAIL_SEND_FAILED`。

请求示例:

```json
{
  "username": "reviewer1",
  "email": "reviewer1@example.com",
  "turnstileToken": "cloudflare-turnstile-token"
}
```

`POST /api/auth/password-reset/confirm`
- 权限:公开。
- 请求关键字段:`username`、`email`、`code`、`newPassword`、`confirmPassword`。
- `code` 为 6 位数字验证码; `newPassword` 和 `confirmPassword` 必须一致且长度 6-72。
- 验证成功后更新密码; 若账号原邮箱为空,同步绑定本次验证邮箱。
- 常见错误:`PASSWORD_CONFIRM_MISMATCH`、`PASSWORD_RESET_CODE_INVALID`、`PASSWORD_RESET_FAILED`。

请求示例:

```json
{
  "username": "reviewer1",
  "email": "reviewer1@example.com",
  "code": "123456",
  "newPassword": "newpass123",
  "confirmPassword": "newpass123"
}
```

邮件配置环境变量:

- `LABELHUB_MAIL_HOST`: SMTP 主机,QQ 邮箱为 `smtp.qq.com`。
- `LABELHUB_MAIL_PORT`: SMTP 端口,QQ SSL 默认 `465`。
- `LABELHUB_MAIL_USERNAME`: 发件邮箱账号。
- `LABELHUB_MAIL_PASSWORD`: SMTP 授权码,不得写入代码仓库。
- `LABELHUB_MAIL_FROM`: 发件人邮箱。
- `LABELHUB_MAIL_SSL_ENABLED`: 是否启用 SSL。
- `LABELHUB_MAIL_STARTTLS_ENABLED`: 是否启用 STARTTLS。
- `LABELHUB_AUTH_PASSWORD_RESET_CODE_TTL_SECONDS`: 验证码有效期,默认 600 秒。
- `LABELHUB_AUTH_PASSWORD_RESET_RESEND_COOLDOWN_SECONDS`: 重发冷却,默认 60 秒。
- `LABELHUB_AUTH_PASSWORD_RESET_MAX_ATTEMPTS`: 错误验证码最大尝试次数,默认 5。

## 3. Owner 任务与分配

### 3.1 功能说明

Owner 任务接口负责创建、编辑、查询、发布/暂停/结束任务,并提供可分配标注员、审核员列表。任务创建时可绑定数据集、Schema 模板、分配策略、奖励、截止时间、AI 预审规则、LLM 标注助手和题目范围。

### 3.2 典型流程

1. Owner 查询数据集、模板、可分配人员。
2. 调用 `POST /api/tasks` 创建草稿或发布任务。
3. 需要修改时调用 `PUT /api/tasks/{taskId}`。
4. 发布、暂停、结束或续期后发布通过 `PUT /api/tasks/{taskId}/state` 或任务更新接口完成。
5. Labeler 从任务市场领取任务。

### 3.3 接口列表

- `GET /api/tasks`
- `POST /api/tasks`
- `GET /api/tasks/{taskId}`
- `PUT /api/tasks/{taskId}`
- `DELETE /api/tasks/{taskId}`
- `PUT /api/tasks/{taskId}/state`
- `GET /api/tasks/assignable-labelers`
- `GET /api/tasks/assignable-reviewers`

### 3.4 关键字段

任务请求关键字段:

- `title`:任务标题。
- `taskType`:任务类型,如 `qa_quality`、`preference_compare`。
- `status`:目标状态,`draft / published / paused / ended`。
- `datasetId`:绑定数据集。
- `schemaVersionId`:绑定模板版本。
- `strategy`:分发策略,`first-come / assigned / quota`。
- `quota`:总配额。
- `maxClaimPerUser`:单个标注员最大领取数。
- `assignedLabelerIds`:指派标注员。
- `labelerAllocations`、`reviewerAllocations`:按人员分配题量。
- `itemSelectionMode`:题目范围,`all / partial`。
- `selectedItemIds`:部分题目模式下的题目 ID。
- `reward`:单题奖励金额。
- `deadline`:任务截止时间。
- `aiReviewEnabled`、`aiReviewRuleId`:AI 预审配置。
- `llmAssistEnabled`:是否开启标注员 LLM 助手。

任务响应关键字段:

- `taskId`、`title`、`state`、`taskType`。
- `quotaUsed`、`quotaTotal`、`annotatedItemCount`、`publishedItemTotal`。
- `reviewStatus`、`reviewRound`。
- `assignedLabelerIds`、`aiReviewEnabled`、`aiReviewRuleName`。
- `deadline`、`reward`、`tags`、`description`。

### 3.5 权限与错误

- 权限:Owner 任务管理接口仅 owner。
- 常见错误:`TASK_NOT_FOUND`、`DATASET_NOT_FOUND`、`SCHEMA_NOT_FOUND`、`INVALID_ASSIGN_STRATEGY`、`TASK_ITEMS_REQUIRED`、`DATASET_REQUIRED`、`LABELER_NOT_FOUND`、`REVIEWER_NOT_FOUND`、`MONTHLY_REWARD_CAP_EXCEEDED`。

## 4. 数据集管理

### 4.1 功能说明

数据集模块负责 Owner 创建数据集、导入数据文件、查看数据条目、为任务或模板提供题目选项。支持 `qa_quality` 和 `preference_compare` 等类型,保留多模态字段。

### 4.2 接口列表

- `GET /api/datasets`
- `POST /api/datasets`
- `POST /api/datasets/import`
- `POST /api/datasets/{datasetId}/items/import`
- `GET /api/datasets/{datasetId}/items`
- `GET /api/datasets/{datasetId}/item-options`
- `DELETE /api/datasets/{datasetId}`

### 4.3 关键接口说明

`GET /api/datasets`
- 权限:owner。
- 返回分页数据集元信息。
- 关键字段:`id`、`name`、`kind`、`description`、`itemCount`、`size`、`importedAt`、`mediaDistribution`、`version`、`importStatus`。

`POST /api/datasets`
- 权限:owner。
- 请求关键字段:`name`、`kind`、可选 `taskId`。
- 用于先建数据集元信息。

`POST /api/datasets/import`
- 权限:owner。
- 类型:`multipart/form-data`。
- 请求字段:`name`、`kind`、可选 `taskId`、`file`。
- 文件大小限制当前为 20MB。

`POST /api/datasets/{datasetId}/items/import`
- 权限:owner。
- 类型:`multipart/form-data`。
- 向已有数据集导入或追加条目。

`GET /api/datasets/{datasetId}/item-options`
- 权限:owner。
- 用于任务创建时选择部分题目。
- 关键字段:`itemId`、`itemKey`、`label`、`mediaType`、`summary`。

### 4.4 常见错误

- `DATASET_NOT_FOUND`:数据集不存在或无权访问。
- `EMPTY_DATASET_FILE`:未上传文件。
- `DATASET_FILE_TOO_LARGE`:文件超过限制。
- `INVALID_DATASET_KIND`:数据集类型不支持。
- `INVALID_DATASET_ROW`:行数据无法序列化。
- `INVALID_DATASET_FILE`:文件无法读取。

## 5. 模板与 Schema

### 5.1 功能说明

Schema 模块支持 Owner 搭建标注模板、保存草稿、校验、发布、撤回和删除。模板字段由物料组成,包括输入、选择、富文本、文件、JSON、LLM 触发、展示项和布局容器。

### 5.2 接口列表

- `GET /api/schemas`
- `GET /api/schemas/{versionId}`
- `POST /api/schemas/draft`
- `POST /api/tasks/{taskId}/schemas/draft`
- `POST /api/schemas/validate`
- `PUT /api/schemas/{versionId}/draft`
- `POST /api/schemas/{versionId}/publish`
- `POST /api/schemas/{versionId}/withdraw`
- `DELETE /api/schemas/{versionId}`

### 5.3 关键字段

Schema 草稿请求关键字段:

- `name`:模板名称。
- `description`:模板说明。
- `taskId`:可选绑定任务。
- `datasetId`、`datasetName`:默认关联数据集。
- `tabs`:表单页签。
- `fields`:字段定义。

字段定义关键字段:

- `kind`:物料类型,如 `text-single`、`single-choice`、`show-item`、`group`、`multi-tab`。
- `fieldName`:提交答案中的字段名。
- `label`:展示名称。
- `required`:是否必填。
- `options`:选择项。
- `sourcePath`:ShowItem 从原题 `rawPayload` 读取的路径。
- `validators`:结构化校验规则。
- `reactions`:字段联动规则。
- `children`:分组容器子字段。

`POST /api/schemas/validate`
- 权限:owner。
- 返回 `valid`、`errors`、`warnings`。
- 用于模板保存/发布前校验字段名、必填项、联动规则和布局配置。

### 5.4 常见错误

- `SCHEMA_NOT_FOUND`:模板版本不存在。
- `INVALID_SCHEMA`:模板结构非法。
- `SCHEMA_FIELD_REQUIRED`:字段缺失。
- `DUPLICATE_FIELD_NAME`:字段名重复。
- `FORBIDDEN`:非 owner 访问。

## 6. Labeler 工作台

### 6.1 功能说明

Labeler 工作台覆盖任务市场、领取任务、我的任务、答题页、草稿箱、批量提交、返修项、题目反馈、附件上传下载和 LLM 辅助。

### 6.2 典型流程

1. Labeler 调用 `GET /api/market/tasks` 浏览可领取任务。
2. 调用 `POST /api/tasks/{taskId}/claim` 领取一个作业项。
3. 进入答题页调用 `GET /api/assignments/{assignmentId}/item` 获取原题、Schema、草稿和历史链路。
4. 答题中调用 `PUT /api/assignments/{assignmentId}/draft` 自动保存。
5. 提交时调用 `POST /api/assignments/{assignmentId}/submit`。
6. 被打回后在 `GET /api/labeler/returned-items` 查看返修项并重新提交。

### 6.3 任务市场与领取

接口:

- `GET /api/labeler/overview`
- `GET /api/market/tasks`
- `GET /api/market/tasks/stats`
- `POST /api/tasks/{taskId}/claim`
- `GET /api/assignments/mine`

`GET /api/market/tasks`
- 权限:labeler。
- 查询参数:`keyword`、`taskType`、`strategy`、`mediaType`、`aiReview`、`sortBy`、`page`、`pageSize`。
- 返回任务市场卡片,关键字段包括 `taskId`、`title`、`taskType`、`remainingQuota`、`totalQuota`、`deadline`、`rewardPerItem`、`assignStrategy`、`mediaTypes`、`ownerName`、`aiReviewEnabled`、`llmAssistEnabled`、`claimable`、`rewardCapExceeded`。

`POST /api/tasks/{taskId}/claim`
- 权限:labeler。
- 后端根据任务分配策略、剩余配额、个人领取上限、月度奖励上限和任务截止状态判断是否可领取。
- 返回 `Assignment`,关键字段:`assignmentId`、`taskId`、`itemId`、`status`、`schemaVersionId`、`deadline`、`hasDraft`、`hasSubmittedAnnotation`。

`GET /api/assignments/mine`
- 权限:labeler。
- 可用 `status` 过滤我的任务列表。

### 6.4 答题、草稿与提交

接口:

- `GET /api/assignments/{assignmentId}/item`
- `GET /api/assignments/{assignmentId}/draft`
- `PUT /api/assignments/{assignmentId}/draft`
- `DELETE /api/assignments/{assignmentId}/draft`
- `GET /api/labeler/drafts`
- `POST /api/assignments/{assignmentId}/submit`
- `POST /api/tasks/{taskId}/assignments/submit`

`GET /api/assignments/{assignmentId}/item`
- 权限:当前 assignment 所属 labeler。
- 返回答题页完整数据。
- 关键字段:`rawPayload`、`tabs`、`fields`、`position`、`draft`、`latestAnnotation`、`editable`、`deadline`、`resubmitDeadline`、`lockReason`、`contribution`、`itemHistory`。
- Labeler 标注页不应展示标准答案或参考答案字段,只展示原题和需要作答的信息。

`PUT /api/assignments/{assignmentId}/draft`
- 权限:当前 assignment 所属 labeler。
- 请求关键字段:`answerJson`、可选 `schemaDigest`。
- 返回草稿 `assignmentId`、`answerJson`、`updatedAt`。

`POST /api/assignments/{assignmentId}/submit`
- 权限:当前 assignment 所属 labeler。
- 请求关键字段:`schemaVersionId`、`answerJson`、可选 `schemaDigest`、`draftVersion`。
- 返回正式 `Annotation`,并触发后续 AI 预审或人工审核流程。

`POST /api/tasks/{taskId}/assignments/submit`
- 权限:labeler。
- 批量提交当前任务下已领取且有草稿的作业。
- 返回 `submittedCount`、`annotationIds`。

### 6.5 返修与审核链路

接口:

- `GET /api/labeler/returned-items`

`GET /api/labeler/returned-items`
- 权限:labeler。
- 查询参数:`source`、`keyword`、`page`、`pageSize`。
- `source` 支持 `all / human_return / reworked / reviewed / ai_pre_reject`。
- 返回人工打回、AI 预打回和返修后审核结果。
- 关键字段:`sourceLabel`、`taskTitle`、`reviewerName`、`reviewStageLabel`、`humanReason`、`aiDecision`、`aiComment`、`aiRiskFlags`、`resubmitDeadline`、`editable`、`actionable`、`reworkStatusLabel`、`reviewTimeline`。
- 争议升级后同一 annotation 内后续 `APPROVE / RETURN` 展示为终审通过/终审驳回。

### 6.6 题目反馈、附件与 LLM 辅助

接口:

- `POST /api/assignments/{assignmentId}/issues`
- `POST /api/assignments/{assignmentId}/attachments`
- `GET /api/assignments/{assignmentId}/attachments/{fileId}/download`
- `POST /api/labeler/assignments/{assignmentId}/assistant`
- `POST /api/labeler/assignments/{assignmentId}/llm-trigger`

`POST /api/assignments/{assignmentId}/issues`
- 权限:当前 assignment 所属 labeler。
- 请求字段:`category`、`description`。
- `category` 支持 `data_error / schema_mismatch / media_broken / duplicate / sensitive / other`。
- 返回 `issueId`、任务和题目标识、状态和创建时间。

附件接口
- 上传使用 `multipart/form-data`。
- 下载返回文件流。
- 权限限定在 assignment 关联用户和有权查看该 assignment 的角色。

LLM 接口
- `assistant` 是答题页通用助手,请求字段 `question`、可选 `history`。
- `llm-trigger` 是字段级生成建议,请求字段 `triggerFieldName`、目标字段和 `currentAnswerJson`。
- 二者均为 SSE 流式响应,前端接收增量内容和最终结果。

### 6.7 常见错误

## 12. 当前 Swagger 覆盖范围

当前 Swagger 由 SpringDoc 扫描后端 `@RestController` 生成,覆盖后端实际暴露的 HTTP API。按模块统计如下:

- `auth`:登录、注册、当前用户、退出、Reviewer/Owner 邀请。
- `tasks`、`market`、`assignments`:Owner 任务、任务市场、领取、答题、草稿、附件、提交、题目反馈。
- `datasets`:数据集元信息、导入、条目和选项。
- `schemas`:模板草稿、校验、发布、撤回、删除。
- `labeler`:Labeler 概览、草稿箱、返修项、LLM 辅助。
- `reviewer`:Reviewer 概览、批次、AI 复核、人工裁决、争议、报表。
- `ai-review`:AI 规则、作业、结果、模型配置、AI 看板。
- `dashboard`:Owner 数据看板、题目反馈、报表。
- `reviews`:Owner 人工审核只读跟踪与审计。
- `exports`:导出中心。

不属于 Swagger 覆盖范围的内容:

- 前端页面路由,如 `/docs`、`/about`、`/owner/tasks`。
- 前端静态资源,如 `/sample-datasets/...`。
- 外部链接、公开文档预览逻辑、下载 ZIP 的前端组装逻辑。
- Service 内部方法、数据库迁移脚本、定时任务内部逻辑。

## 26. Owner 审核明细题号语义说明

- `GET /api/reviews/tasks/{taskId}/annotations` 的响应字段 `itemIndex` 继续保持字段名和类型不变。
- `itemIndex` 语义调整为“该条目在当前任务范围内的 1-based 全局题序”。
- 新任务优先使用 `task_items.position_no` 作为题号来源。
- 历史任务缺少 `task_items` 快照时,后端按任务内 `item_id` 做稳定回退,避免返回空题号。
- 如果同一个任务条目被多个标注员标注,多行返回相同 `itemIndex` 是正确表现,表示这些标注记录对应同一道任务题目。
- Owner 审计日志、任务审计导出 CSV 和条目时间线同步采用相同题号口径。
- Labeler 答题页的本地作答序号不受本轮调整影响。
